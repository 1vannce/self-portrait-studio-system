# Project Structure Guide

This guide explains what each folder in the repository is for and how the parts connect. It is written for anyone browsing the code for the first time, including our instructor. For the design rules behind it, see [ARCHITECTURE.md](ARCHITECTURE.md).

> **Current stage:** foundation. Login, the database schema for all three subsystems, the Supabase clients, integration settings, tests, and CI are in place. The business screens are not built yet.

## The big picture

The Self Portrait Studio System is a web app for **OH MEDIA Studio**, a self-portrait photography studio. It covers three business subsystems:

| Subsystem | What it handles | Database tables |
| --- | --- | --- |
| Booking & Reservation | Studio services, time slots, customer reservations | `services`, `time_slots`, `reservations` |
| Point of Sale & Billing | Orders, order items, payments, receipts | `orders`, `order_items`, `payments`, `receipts` |
| Inventory & Supply | Suppliers, stock items, stock movements | `suppliers`, `inventory_items`, `stock_movements` |

All three share one `profiles` table for users (admin, staff, customer).

It is one **Next.js** app. Pages and server code live in the same project. Supabase provides the database, login, and file storage.

```text
 Browser  ->  src/proxy.ts (refresh login session)  ->  Next.js page or route (src/app)
                                                            │
                                     ┌──────────────────────┼──────────────────────┐
                                     ▼                      ▼                      ▼
                             Supabase Auth           Drizzle ORM (src/db)    Outside services
                             (src/lib clients)       -> Supabase PostgreSQL  (Botcake, payments, Contavo)
```

| Part | Technology | Job |
| --- | --- | --- |
| Pages and UI | Next.js 16 App Router, Tailwind CSS, shadcn/ui | What the user sees |
| Login | Supabase Auth | User accounts and sessions |
| Database | Supabase PostgreSQL | Stores all records |
| Database access | Drizzle ORM + postgres.js | Typed tables and queries |
| Validation | Zod + drizzle-zod | Checks input against the table rules |
| Outside services | Botcake, a payment service, Contavo | Messaging, payments, operations (planned) |
| Tests | Vitest | Automated checks |

## Inside `src/`

```text
src/
├── proxy.ts                   # Runs before every page request and refreshes the Supabase login session
│                              # (Next.js 16 calls this file "proxy"; older versions called it "middleware")
│
├── app/                       # PAGES AND ROUTES. Each folder is a URL.
│   ├── layout.tsx             # The outer frame of every page (fonts, global styles)
│   ├── page.tsx               # The home page "/"
│   ├── globals.css            # Tailwind and theme colors
│   ├── auth/
│   │   ├── layout.tsx         # Centered layout for the sign-in screens
│   │   ├── login/page.tsx     # "/auth/login": email and password sign-in
│   │   └── callback/route.ts  # "/auth/callback": Supabase sends users here after an email link, to start their session
│   └── api/health/route.ts    # GET /api/health -> { status: "ok" }. Used to check the app is running.
│
├── db/                        # DATABASE
│   ├── schema.ts              # Every table and enum, grouped by subsystem, plus Zod schemas made from the tables
│   └── index.ts               # The one Drizzle database client (server only, reads DATABASE_URL)
│
├── lib/                       # Shared helpers
│   ├── client.ts              # Supabase client for the browser (used by the login page)
│   ├── server.ts              # Supabase client for server code (reads the login cookie)
│   ├── proxy.ts               # updateSession(): the session refresh logic used by src/proxy.ts
│   ├── utils.ts               # cn() helper for combining CSS class names
│   └── integrations/
│       └── contracts.ts       # Reads the URL and API key for Botcake, the payment service, and Contavo (server only)
│
├── components/ui/             # Reusable UI building blocks from shadcn/ui (Button, and more as they are added)
│
└── __tests__/                 # Vitest tests
    ├── db/schema.test.ts      # Checks the tables, enums, and Zod schemas are defined as expected
    └── lib/integrations/contracts.test.ts # Checks integration settings fail clearly when a value is missing
```

## How `src/db/schema.ts` is organized

The schema file is split into sections with comment headers, so you can read it top to bottom:

1. **Enums**: fixed lists such as `user_role` (admin, staff, customer), `reservation_status`, `order_status`, `payment_method`, `payment_status`, `stock_movement_type`.
2. **Shared**: `profiles`, one row per user.
3. **Subsystem 1, Booking & Reservation**: `services`, `time_slots`, `reservations`.
4. **Subsystem 2, POS & Billing**: `orders`, `order_items`, `payments`, `receipts`.
5. **Subsystem 3, Inventory & Supply**: `suppliers`, `inventory_items`, `stock_movements`.
6. **Cross-subsystem link**: how an order item can point to an inventory item.

A change to this file is turned into SQL with `npm run db:generate`, which writes a new file in `drizzle/`.

## Follow one action: signing in

1. The user opens `/auth/login`. `src/proxy.ts` runs first and refreshes any existing session.
2. `src/app/auth/login/page.tsx` sends the email and password to Supabase Auth using the browser client in `src/lib/client.ts`.
3. Supabase checks the password and sets a session cookie.
4. On later requests, server code uses `src/lib/server.ts` to read that cookie and know who is logged in.
5. When business pages are added, server code will read and write data through `src/db/index.ts`, never from the browser.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the app at `http://localhost:3000` |
| `npm run lint` | Check code style |
| `npm run test:run` | Run the tests once |
| `npm run build` | Build for production (also checks TypeScript) |
| `npm run db:generate` | Create a migration from changes in `src/db/schema.ts` |
| `npm run db:migrate` | Apply migrations to the database in `DATABASE_URL` |
| `npm run db:studio` | Browse the database in Drizzle Studio |
